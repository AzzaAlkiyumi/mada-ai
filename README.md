# Rafeeq — personal self-hosted AI assistant

A single-user chat assistant. Answers are generated by an open-weight model
running on your own machine or server — no paid AI API.

```
Browser ──▶ React (frontend/) ──▶ Laravel API (backend/) ──▶ MySQL
                                        └──▶ llama.cpp server (model-engine/, 127.0.0.1 only)
```

| Folder | What it is |
|---|---|
| `backend/` | Laravel 13 API: login (Sanctum cookie session), conversations, streaming chat |
| `frontend/` | React 19 + Vite + Tailwind chat UI (Arabic/English, RTL/LTR, light/dark) |
| `model-engine/` | Script to run llama.cpp; binaries and model weights are downloaded here and git-ignored |

## Run locally (Windows)

Prerequisites: PHP 8.3+, Composer, Node 20+, MySQL (or the MariaDB that ships with XAMPP).

1. **Database** — create a database named `assistant` (utf8mb4), then set the
   `DB_*` values in `backend/.env`.

2. **Backend**
   ```powershell
   cd backend
   composer install
   copy .env.example .env      # first time only
   php artisan key:generate    # first time only
   php artisan migrate
   php artisan user:create     # prompts for name, email, password (min 12 chars)
   php artisan serve --host=127.0.0.1 --port=8000
   ```
   Change the password later with `php artisan user:password`.

3. **Model server** (separate terminal). Put a random value in
   `LLM_API_KEY` in `backend/.env` first; the script reads it from there.
   ```powershell
   powershell -ExecutionPolicy Bypass -File model-engine\start-llama.ps1
   ```
   It listens on `127.0.0.1:8080` only. Stop it with Ctrl+C.

4. **Frontend** (separate terminal)
   ```powershell
   cd frontend
   npm install
   npm run dev
   ```
   Open http://localhost:5173. Vite forwards `/api` and `/sanctum` to Laravel.

## Model settings (`backend/.env`)

| Variable | Meaning |
|---|---|
| `LLM_BASE_URL` | OpenAI-compatible endpoint of the engine (llama.cpp, Ollama, vLLM) |
| `LLM_API_KEY` | Shared secret between Laravel and the engine |
| `LLM_MODEL` | Model name/alias sent to the engine |
| `LLM_MAX_TOKENS` | Maximum reply length |
| `LLM_CONTEXT_MESSAGES` / `LLM_CONTEXT_CHARS` | How much history is sent per request |
| `LLM_MAX_INPUT_CHARS` | Maximum length of one user message |
| `LLM_TIMEOUT` | Seconds before a reply is abandoned |
| `LLM_THINKING` | Enable the model's reasoning mode (slower) |
| `LLM_RATE_PER_MINUTE` | Messages allowed per minute |

Switching engines (e.g. to vLLM on a GPU server) only needs a different
`LLM_BASE_URL` / `LLM_MODEL`; the code lives behind
`App\Services\Llm\LlmClient`.

## Tests

## Backup and restore (MySQL)

```powershell
mysqldump --single-transaction -u USER -p assistant > backup.sql
mysql -u USER -p assistant < backup.sql
```

## Notes for local development

- `php artisan serve` handles one request at a time on Windows, so the
  conversation list waits while a reply is streaming. Production uses
  PHP-FPM and does not have this limit.
- Production deployment (Contabo VPS, Nginx, HTTPS, firewall, systemd,
  backups) is described in [deploy/README.ar.md](deploy/README.ar.md).
